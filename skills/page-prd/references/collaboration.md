# Git 正文与共享评审

## 正文发布

本地页面设计通过浏览器验收后，同步对应 Markdown 及资源；一次明确变更同时提交页面代码、文档、绑定和按要求生成的修订。团队合并冲突逐项按确认结论处理，不整文件覆盖其他产品的内容。

测试环境部署合并后的相同版本，正式正文只读。后续发布会更新构建内的正文和资源，而非覆盖远端在线编辑；产品拉取远端合并代码与文档，再比较本地页面与测试环境。浏览器缓存及旧构建资源应更新，避免新页面读到旧文档。

同页多人修改 `.md` 由 Git 合并和评审。manifest 改动注意保留所有页面、父级及原有历史；新增图片随正文提交，不提交本机绝对路径或临时目录。发布前不运行能够写入源文件的在线保存服务。部署 base、反代和现有业务路由保持。

## 评论评审

正式共享评论独立于源码和构建包，至少记录：项目或租户、稳定页面 id、文档版本、评论 id、作者、时间、正文、原文摘录/锚点、回复、解决状态。读取和写入经项目 API 层及实际用户权限；前端显示只读不是后端权限控制。

正文更新后保留评论历史。仍可定位则继续关联；引用失效时显示“原文已变更”，保留摘录与评论，不悄悄删除、重新绑定或标记已解决。发布新静态包不替换评论数据库。

本包参考界面的评论、回复、身份和解决状态仅在页面内存演示，刷新恢复，不具备共享后端。演示标签必须可见；不能宣称上线多人协作。需要真实共享时先确认现有后端、认证、数据归属和协议，再做实施；技能安装不等于批准新增后端或第三方账号。

## 自动保存与版本

本地读取返回内容及文件内容哈希，保存携带读取版本；服务端同文件串行校验并写入，不一致返回冲突。失败保留修改；不要用空 catch、旧草稿或自动重试覆盖他人版本。保存期间有新输入则继续写最新快照，全部成功才显示已保存。

文档“完成编辑”不应让页面业务自动提交。当前项目约定不新增修订时只保存正文；若以后需要自动生成修订，以确认后的完整变更为单位，在既有结构增加一次，不能按键追加记录。
