# 页面旁功能 PRD

沿用真实业务页面和原地址，每页绑定一份版本库内的 Markdown。优先维护已有集成；首次接入才使用随包参考源码。技能安装只安装指导与资源，不自动安装页面组件、修改业务路由或启动服务。

## 工作流程

**修改页面 → 浏览器验证 → 验证确认通过 → 更新页面旁的 PRD → 按需导出。**

1. 先读项目约定、需求、页面源码及现有 PRD，确定真实页面名称、功能归属与入口关系。已有确认内容保留，无关模块不变。
2. 若修改页面，按项目要求先更新开发需求文档；浏览器验证布局、交互及受影响状态，通过后再同步用户阅读的页面 PRD。仅补文档时核对现页，不强行改业务。历史要求与实现不同时明确标注差异、待实现或待确认。
3. 每页维护独立 `.md`，页面及父子关系登记在 manifest，不将 PRD 再拆回前端字段 JSON。内容覆盖标准见 [正文规范](references/content-standard.md)。
4. 运行绑定检查及项目相关检查；在原业务地址验证目录跟随、独立查看和收起效果。未能完成浏览器验收时如实说明范围，不能用构建成功代替。
5. 按需导出；没有请求不额外生成导出物。交付说明受影响文档、验证结果与未接入能力，不自动提交或推送。

## 原页面与文档的关系

- 地址栏保留业务原地址及 query/hash，登录、鉴权、布局、接口继续原行为。PRD 不注册、替换或重定向业务路由，不要求改用独立预览端口。
- 默认收起，只保留贴右侧、透明底色、无阴影的 PRD 入口；可上下拖动、键盘移动，限制在可见范围，拖动松手不展开。只能将位置等界面偏好存入浏览器，正文以项目文件为准。
- 收起时页面恢复完整可用宽度；无额外头部、空栏、分隔区域、编号、红框、高亮或注入样式。后台任务不得重新加回效果。
- 展开时给侧栏让出空间；窄屏可覆盖展示。业务组件不重新挂载，表单草稿、控件与滚动不被重置。侧栏中的 iframe 只承载文档，不再次嵌套业务页面。
- 头部为“功能模块名称 PRD”，采用平台既有字体、颜色和图标；编辑/完成、评论、更多、收起使用紧凑图标按钮并提供悬停和无障碍名称。不增加另一套工具栏和模式页签。
- 左目录、右正文；目录名称与真实目标页面标题一致。默认页为一级，子页以实际入口登记父级并编号，不按 URL 深度推测；弹窗、页签在所属页说明，不虚构路由。工作台即使在新标签或独立布局，也按真实入口归属模块。
- 业务导航后目录自动选中对应页，包括同类详情切换对象；目录点击只切换文档，不导航业务、改变参数或丢弃草稿。下一次真实导航恢复跟随。未登记路由不借用其他正文。
- 目录名称和序号默认单行，长名称省略且悬停完整显示；目录可单独拖宽或通过方向键调宽。修订记录固定在目录最上方，点击独立阅读，不占业务页正文顶部。

## Markdown 编辑与图表

在正文原位置切换阅读/编辑，Enter、Shift+Enter、输入法、撤销和常用格式正常工作。源码从更多菜单按需打开，不再套一层 Markdown 编辑器外壳。支持标题、段落、列表、表格、图片和 Mermaid；选择编辑器或引入依赖遵守项目约定，不因本技能视为已获批准。

本地自动保存到绑定 `.md`，显示保存中/已保存/失败/冲突；请求中继续输入不得误标已全部保存。切页或完成编辑等待保存；失败保留输入，版本冲突停止覆盖并可备份。收起不销毁待保存内容；离开有未保存修改须保护。不得把 localStorage 草稿或导出下载冒充落盘成功。

图片保存为项目相对资源，与正文提交。Mermaid 源码保留在代码块中，按需加载引擎；图表弹窗源码与实时预览并排，错误提示且禁止应用，可插入、编辑、放大、删除，阅读仅放大。若沿用轻量转换器，明确其 Markdown 支持范围，复杂嵌套格式验证往返后再编辑，不能承诺任意 Markdown 无损。

## 修订与团队协作

- “正式维护”与“是否记修订”独立。用户说“不新增修订记录”时，正文照常正式更新，保留历史，不改成调试文案，也不因点击完成编辑自动加记录。
- 需要记修订时，在一轮已验证确认的实际功能调整后记一次日期和具体内容；刷新、切页、导出及无变化确认不记。使用当前用户所在地日期。已有实现未自动记记录时，不声称具备该能力。
- **正文及图片走 Git，评论走独立评审数据。** 本地设计和 Markdown 一起提交、团队合并、测试环境构建只读发布；产品再拉取合并结果核对。只读正文随发布更新，不存在应覆盖的远端在线正文草稿。
- 远端不调用本地文件保存或 mock 接口，不暴露本机路径。若远端已有在线正文编辑，先确认迁移与合并方案，不能直接覆盖。
- 评论需求覆盖整页/选文批注、回复、解决/重开、筛选，关联稳定文档 ID、版本和原文摘录；正文更新不清空评论，锚点失效保留摘录并标记。共享评论需要实际认证、持久化及后端协议；缺少服务只能明确展示演示，不得把当前页临时数组称为多人共享。
- 评论默认隐藏，按需展开，收起 PRD 同时关闭浮动工具。评论与正文权限分开；部署或合并不得用静态包替换共享评审数据库。详见 [协作与发布](references/collaboration.md)。

## 文件、工具与首次接入

- 已有项目：沿用当前 manifest 和文档目录，保留所有无关页面及历史；不用本包示例覆盖现有文件。schema 见 [页面绑定](references/manifest.md)。
- 首次接入 Vue/Vite：阅读 [集成指南](references/integration.md)，按目标项目适配 `assets/integration-source/`。这些是可审查的参考源码，不是自动安装插件；其他框架沿用行为契约，不强塞 Vue。
- 示例结构在 `assets/templates/`；仅用于首次建文档，示例地址不注册为业务路由。
- 旧 HTML/spec 升级：先提取全部已确认正文和修订，再按实际页迁移到 `.md` 和 manifest；核对页面、字段、提示及历史后停用旧入口。不要再运行旧 `merge-spec.mjs --confirmed` 写回整份内联 JSON，也不默认启用旧编号覆盖层。

从技能目录运行以下命令，项目路径和输出路径按实际填写；脚本只查文件和导出，不执行浏览器验收或业务写入。

```sh
node scripts/check-manifest.mjs /项目目录/designs/prd-review-v1/manifest.json
node scripts/export-md.mjs /项目目录/designs/prd-review-v1/manifest.json /输出目录/项目管理.md --module 项目管理
node scripts/export-md.mjs /项目目录/designs/prd-review-v1/manifest.json /输出目录/单页.md --page project-create
```

模块导出按父子目录顺序，包含一次既有修订；单页导出保留所属模块标题及原目录编号。当前参考 UI 的下载按钮只导出当前页，完整模块使用脚本；不得承诺已有 UI 没实现的导出范围。HTML/PDF 仅在用户提出且项目具备相应能力时处理。

交付前按 [验收清单](references/acceptance.md) 检查；结构通过只说明绑定有效，不说明业务完整、共享后端已上线或浏览器验收通过。
